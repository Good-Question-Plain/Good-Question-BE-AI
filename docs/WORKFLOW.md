# WORKFLOW.md

이 문서는 모든 작업의 절차 기준이다. 새 세션 시작 시 1회 읽는다.

---

## 1. 세션 초기화 규칙

### 새 세션 기준

- **개념 기준**: 컨텍스트가 비어있는 상태의 첫 요청
- **실용 기준**: 현재 세션에서 PRD / TRD / WORKFLOW를 아직 읽지 않은 상태

### 초기 로드 순서

1. `docs/PRD.md` — 없으면 건너뜀
2. `docs/TRD.md` — 없으면 건너뜀
3. `docs/WORKFLOW.md` — 없으면 **반드시 사용자에게 알림** (작업 절차 기준 문서이므로 건너뛰지 않음)

### 로드 완료 후

"PRD / TRD / WORKFLOW 로드 완료, 작업 준비됐습니다." 한 줄 출력 후 작업 대기.

### 세션 중 문서 참조

- 이미 읽은 내용에서 사용. 부분 재로드 없음.
- 재로드 조건:
  - 사용자가 명시적으로 재로드 요청한 경우
  - 문서가 변경되었고 최신 내용 반영을 요청한 경우

---

## 2. 작업 절차

### 1차 — 설계

1. 요구사항 핵심 파악
2. 해결 방향 탐색 (선택지가 있을 경우 제시)
3. 구체적 구현 방식 설계 (구조, 데이터 흐름, 기술 선택 근거)
4. 사용자에게 설계 내용 제출 → **승인 대기**
5. 승인 후 설계 결과를 아래 경로로 저장:
   `docs/designs/{feature} YYYY-MM-DD HH:MM.md`

### 2차 — 구현

1. 1차 승인된 설계 문서(`docs/designs/`)를 기준으로 구현
2. 구현 완료 후 사용자에게 보고

### 3차 — 검증 (새 세션 서브 에이전트)

현재 세션의 컨텍스트 오염을 배제하기 위해 **별도의 새 세션**에서 서브 에이전트를 실행하여 검증한다.

#### 서브 에이전트에 제공할 컨텍스트

| 순서 | 문서 | 역할 |
|------|------|------|
| 1 | `docs/PRD.md` | 사용자 요구사항 기준 |
| 2 | `docs/TRD.md` | 기술 설계 기준 |
| 3 | `docs/designs/{feature} YYYY-MM-DD HH:MM.md` | 1차 설계 기준 |
| 4 | 구현된 코드 | 검증 대상 |

#### 검증 항목

- 사용자 요구사항(PRD) 대비 구현 일치 여부
- 1차 설계 대비 구현 일치 여부
- 버그, 누락, 개선 필요 항목 식별

#### 검증 결과 처리

- **문제 없음**: 완료
- **문제 발견**: 피드백 목록 정리 → 2차 재진입

---

## 3. 설계 파일 규칙

- **경로**: `docs/designs/{feature} YYYY-MM-DD HH:MM.md`
- **작성 시점**: 1차 설계 완료 및 사용자 승인 직후
- **역할**: 2차 구현의 기준, 3차 서브 에이전트의 검증 기준
- **내용 구성 예시**:
  - 구현 범위
  - 구조 및 데이터 흐름
  - 기술 선택 근거
  - 사용자 승인 내용 요약
