# Auth 설계 — 2026-08-07 01:37

## 구현 범위

이메일 회원가입/로그인(OTP 2차 인증) + 소셜 로그인(Google, Kakao, Naver)

## 엔드포인트

| Method | Path | 설명 |
|---|---|---|
| POST | /auth/register | 이메일 회원가입 (OTP 발송) |
| POST | /auth/verify-email | OTP 인증 |
| POST | /auth/login | 로그인 (Access + Refresh Token 발급) |
| POST | /auth/refresh | Access Token 갱신 |
| POST | /auth/logout | 로그아웃 (Refresh Token 무효화) |
| GET | /auth/{provider}/login | 소셜 로그인 URL 리다이렉트 |
| GET | /auth/{provider}/callback | 소셜 로그인 콜백 |

- `aiosmtplib` — 비동기 SMTP

## 신규 환경변수

| 환경변수 | 기본값 | 용도 |
|---|---|---|
| CORS_ORIGINS | http://localhost:3000 | 허용 Origin 목록 (콤마 구분) |
| OTP_EXPIRE_MINUTES | 5 | 이메일 인증 OTP 유효기간 |
| OAUTH_STATE_EXPIRE_MINUTES | 10 | 소셜 로그인 state CSRF 유효기간 |

## 데이터 흐름

### 이메일 회원가입
```
register → 이메일 중복 확인 → bcrypt 해싱 → caregiver INSERT (is_verified=False)
        → OTP 생성 → Redis SET otp:{email} TTL OTP_EXPIRE_MINUTES분 → SMTP 발송
verify-email → Redis GET otp:{email} → 비교 → is_verified=True → Redis DEL
```

### 로그인
```
login → 이메일·비밀번호 검증 → is_verified 확인
      → Access Token(15분) + Refresh Token(7일) 발급
      → Redis SET refresh:{user_id} TTL 7일
refresh → Refresh Token 디코드 → Redis 값 일치 확인 → 새 Access Token 발급
logout → Redis DEL refresh:{user_id}
```

### 소셜 로그인
```
/{provider}/login → state 생성 → Redis SET oauth_state:{state} TTL 10분 → 리다이렉트
/{provider}/callback → state Redis 검증·삭제 → code 교환 → userinfo 조회
                     → caregiver upsert → 토큰 발급
```

## CORS 관리

`main.py`의 `CORSMiddleware`에서 `settings.cors_origins_list`를 읽어 등록.
`CORS_ORIGINS` 환경변수는 콤마로 구분된 문자열, `@property`로 리스트 변환.

## 사용자 승인 내용

- CORS는 main.py에서 CORSMiddleware로 관리, 환경변수로 origins 제어
- OTP_EXPIRE_MINUTES, OAUTH_STATE_EXPIRE_MINUTES 환경변수로 분리
- 기존 ACCESS_TOKEN_EXPIRE_MINUTES, REFRESH_TOKEN_EXPIRE_DAYS 유지
