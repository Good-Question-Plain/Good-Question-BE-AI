# 스토리 AI 연동 설계 — 2026-08-15

## 구현 범위

첨부된 `do_stt` / `make_chat` / `make_report` 를 서버에 그대로 옮기고,
진행(speak)과 학습 리포트 생성에 연결한다.

## 호출 구조

```
POST /progress/.../speak
  → Groq Whisper STT
  → OpenAI 정규화 (do_stt)
  → OpenAI 심판 check_correct_chat (맥락 불일치면 되묻기, json_schema)
  → OpenAI 심판 check_mission_condition (최근 한 쌍, 조건 충족 시 미션 반환)
  → OpenAI 심판 check_end_condition 또는 max_turns
  → OpenAI 캐릭터 대사 (make_chat)
  → 장면 종료 시 closing 후 messages 플러시

POST /reports/{story_id}/generate
  → 세션 대화 전체를 OpenAI chat_history 로 변환
  → make_report JSON
  → 기존 ReportDraft / 화면 필드로 매핑
```

## 리포트 JSON 매핑

| make_report | 저장/응답 |
|---|---|
| speech_characteristics.comment | speech_summary |
| vocabulary.key_words | report_vocabularies (kind=used) |
| vocabulary.frequent_expressions | expression_patterns |
| expression.*.best_sentence | quotes (실제 아이 발화와 대조) |
| expression.*.feedback | `평가\\n조언` → strength / tip |
| expression.emotion | emotion_expression |
| logic.result_solution | outcome_solution |
| today_key_utterance | representative |
| home_extension.*.question / purpose | home_conversation question / practice_label |

`vocabulary_feedback` 은 첨부 JSON에 없어 주요 어휘 목록으로 한 문장을 만든다.
`curious` 어휘는 이 프롬프트에 없어 비운다.

## 설정

| 환경변수 | 용도 |
|---|---|
| OPENAI_API_KEY / OPENAI_MODEL | 정규화, 장면 심판, 대사, 리포트. 기본 모델 `gpt-5.6-luna` |
| GROQ_API_KEY / GROQ_STT_MODEL | Whisper STT |
| ANTHROPIC_API_KEY | OpenAI 키가 없을 때 기존 리포트 분석기 폴백 |

리포트 분석기 선택: OpenAI → Anthropic → 스텁.
