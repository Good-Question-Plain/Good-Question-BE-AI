## 구현 범위

- `GET /stories` — 스토리 목록 (카테고리 필터, 페이지네이션)
- `GET /stories/recommended` — 추천 스토리 3개 (Redis 10분 캐시)
- `GET /stories/{story_id}` — 스토리 상세 (Redis 1시간 캐시)
- `GET /stories/{story_id}/scenes` — 씬 목록 조회

AI 연동 없음. 스토리 콘텐츠 등록·수정(어드민)은 이번 범위 제외 — 조회 전용이다.

## 값 규약 (이번에 확정)

DB 컬럼은 자유 문자열이지만 다음 값만 사용한다.

| 컬럼 | 허용값 |
|------|--------|
| `stories.status` | `draft` / `published` |
| `stories.difficulty` | `easy` / `normal` / `hard` |

- 조회 API는 **`status = 'published'` 만 노출**한다. `draft` 스토리는 목록에 없고, 상세·씬 조회 시 404다.
- `difficulty`는 응답 스키마에서 `Literal["easy", "normal", "hard"]`로 선언해 OpenAPI 문서에 규약을 드러낸다. 규약 밖 값이 DB에 들어가면 직렬화 단계에서 실패하므로, 콘텐츠 시딩 시 이 값을 지켜야 한다.
- 카테고리는 별도 컬럼이 없고 `stories.topics` (문자열 배열)를 사용한다. 필터는 `category` 쿼리 파라미터로 받아 `category = ANY(topics)` 로 매칭한다.

## API 스펙

### GET /stories

쿼리: `category` (optional), `limit` (기본 20, 1~50), `offset` (기본 0)

```json
// Response 200
{
  "items": [
    {
      "id": "uuid",
      "title": "할아버지의 낡은 시계",
      "thumbnail_url": "https://...",
      "estimated_minutes": 10,
      "topics": ["가족", "감정"],
      "difficulty": "easy"
    }
  ],
  "total": 12,
  "limit": 20,
  "offset": 0
}
```

정렬은 `created_at DESC`. 캐시하지 않는다 — 필터·페이지 조합이 많아 적중률이 낮고, TRD 캐싱 표에도 목록 캐시는 없다.

### GET /stories/recommended

쿼리: `child_id` (필수)

```json
// Response 200 — StoryListItem 3개
[{ "id": "uuid", "title": "...", "thumbnail_url": "...", "estimated_minutes": 10, "topics": ["용기"], "difficulty": "easy" }]
```

선정 기준: **해당 아이가 아직 시작하지 않은 스토리 우선**, 그 안에서 최신순 3개.

```sql
ORDER BY (EXISTS (SELECT 1 FROM story_sessions
                  WHERE child_id = :child_id AND story_id = stories.id)) ASC,
         created_at DESC
LIMIT 3
```

- 미시작 스토리가 3개 미만이면 이미 진행한 스토리로 채운다. 스토리가 3개 미만이면 그만큼만 반환한다.
- 아이별 진행 이력에 의존하므로 캐시 키는 TRD의 `recommended:{child_age}` 가 아니라 **`recommended:child:{child_id}` (TTL 10분)** 을 쓴다. 나이 기반 키로는 진행 이력을 반영할 수 없다.
- 스토리를 시작한 직후 최대 10분간은 추천 목록에 그 스토리가 남아 있을 수 있다. Phase 5에서 스토리 시작 시 이 키를 무효화하도록 연결한다.

### GET /stories/{story_id}

```json
// Response 200
{
  "id": "uuid",
  "title": "할아버지의 낡은 시계",
  "summary": "...",
  "thumbnail_url": "https://...",
  "difficulty": "easy",
  "topics": ["가족", "감정"],
  "estimated_minutes": 10,
  "scene_count": 4,
  "characters": ["할아버지", "지호"]
}
```

- `characters` 는 씬의 `character_name` 을 씬 순서대로 중복 제거해 만든다.
- PRD의 "너는 이 이야기에서..." 역할 설명은 대응 컬럼이 없어 이번 범위에서 제외한다. 필요하면 `stories` 에 컬럼 추가가 선행돼야 한다.
- 캐시: `story:{story_id}` TTL 1시간.

### GET /stories/{story_id}/scenes

```json
// Response 200
[
  {
    "id": "uuid",
    "scene_order": 1,
    "scene_description": "...",
    "character_name": "할아버지",
    "character_opening": "...",
    "character_closing": "...",
    "image_url": "https://..."
  }
]
```

`scene_goal`, `required_elements`, `conflict`, `preferred_turns`, `max_turns` 는 **응답에서 제외**한다. AI 진행·채점 내부 기준이라 클라이언트에 내려가면 아이에게 목표와 정답이 노출된다. Phase 5의 진행 API는 서버 내부에서 직접 읽어 쓴다.

캐시: `story:{story_id}:scenes` TTL 1시간. TRD의 `scene:{scene_id}` 는 씬 단건 캐시라 목록 조회에는 맞지 않아 스토리 단위 키를 새로 둔다.

## 캐싱

| 키 | 값 | TTL |
|----|----|-----|
| `story:{story_id}` | StoryDetail JSON | 1시간 |
| `story:{story_id}:scenes` | SceneItem 배열 JSON | 1시간 |
| `recommended:child:{child_id}` | StoryListItem 배열 JSON | 10분 |

- 직렬화는 Pydantic `model_dump_json()` / `model_validate_json()` 을 쓴다. UUID·datetime 변환을 직접 다루지 않기 위함이다.
- `draft` 스토리는 캐시에 저장하지 않는다 (조회 자체가 404).
- 콘텐츠 수정 API가 아직 없어 명시적 무효화 로직은 두지 않는다. 어드민 기능이 생기면 저장 시 `story:{story_id}*` 를 지우는 처리가 필요하다.
- Redis 장애 시 조회가 실패한다. 캐시 우회 fallback은 두지 않았다 — 기존 auth 도메인도 Redis 의존이 동일하고, 조용한 성능 저하보다 장애를 드러내는 편이 낫다고 판단했다.

## 인증 / 권한

- 네 엔드포인트 모두 `CurrentUser` (Supabase JWT → `Parent`) 필요.
- `GET /stories/recommended` 만 `child_id` 를 받고, 서비스에서 `child.parent_id == parent.id` 를 검증한다. 실패 시 `ForbiddenError`. 기존 vocabulary 도메인의 `_verify_child_ownership` 과 동일한 패턴이다.
- 스토리 콘텐츠 자체는 아이별 소유 개념이 없어 그 외 엔드포인트는 소유권 검증이 없다.

## 예외 처리

| 상황 | 예외 | HTTP |
|------|------|------|
| 토큰 없음 / 만료 | `UnauthorizedError` | 401 |
| 다른 부모의 자녀 `child_id` | `ForbiddenError("해당 자녀 프로필에 접근할 수 없습니다.")` | 403 |
| 없거나 `draft` 인 스토리 | `NotFoundError("스토리를 찾을 수 없습니다.")` | 404 |

신규 예외 클래스 없이 기존 예외를 재사용한다.

## 라우트 등록 순서

`/stories/recommended` 를 `/stories/{story_id}` **보다 먼저** 선언한다. FastAPI는 선언 순서대로 매칭하므로 순서가 뒤바뀌면 `recommended` 가 `story_id` 로 잡혀 UUID 파싱 422가 난다.

---

## 데이터 흐름

```
Router → Service (캐시 조회 → miss 시 Repository) → Repository → DB
```

- Router: 쿼리 파라미터 검증(`Query(ge=, le=)`), 응답 직렬화
- Service: 소유권 검증, Redis 캐시 read-through, ORM → 스키마 변환
- Repository: `status = 'published'` 조건 포함 쿼리 전담

## 사용자 승인 내용 요약

- 추천 기준: 아직 시작 안 한 스토리 우선 (캐시는 아이 단위로 변경)
- 값 규약: difficulty `easy/normal/hard`, status `draft/published`, published만 노출
- 씬 응답: AI 내부 필드(`scene_goal`, `required_elements`, `conflict`, `preferred_turns`, `max_turns`) 제외
